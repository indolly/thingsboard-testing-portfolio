# 测试策略

## 1. 测试目标

以温度监控为核心场景，验证ThingsBoard单节点环境中的设备数据链路、告警状态转换、实体关系和客户权限隔离，并形成可重复执行的接口回归能力。

## 2. 风险与优先级

| 优先级 | 本项目关注点 |
|---|---|
| P0 | 登录认证、设备接入、遥测持久化、告警创建与恢复、权限隔离 |
| P1 | 仪表板展示、资产关系、规则链转换、异常资源查询 |
| P2 | 搜索、分页、排序和低风险显示问题 |

测试深度按业务风险分配，不机械地为每个接口设计相同数量的用例。

## 3. 核心业务链

```text
租户管理员创建测试资源
        ↓
设备使用访问令牌上报temperature
        ↓
平台保存最新值和历史值
        ↓
规则链转换temperatureF
        ↓
temperature > 50创建MAJOR告警
        ↓
仪表板展示温度和告警
        ↓
客户用户只访问已授权资源
        ↓
temperature <= 50自动清除告警
```

## 4. 测试分层

| 层级 | 主要职责 |
|---|---|
| 手工功能测试 | 验证配置流程、页面展示、状态变化和探索性场景 |
| Postman | 调试接口、核对请求、验证正向/异常场景和串联变量 |
| Pytest接口自动化 | 执行稳定、可维护的核心回归，生成JUnit和Allure结果 |
| UI自动化（计划） | 只覆盖登录、设备查询、遥测展示、告警和权限等核心冒烟流程 |
| Jenkins | 环境预检、自动执行、报告发布和结果留痕 |

## 5. 关键测试设计

### 5.1 告警边界与状态迁移

| 输入 | 预期结果 |
|---:|---|
| 49.9 | 不创建高温告警 |
| 50 | 不创建新告警；活动告警满足恢复条件时清除 |
| 50.1 | 创建`High Temperature`、`MAJOR`告警 |

告警流程同时验证`ACTIVE_UNACK → ACTIVE_ACK → CLEARED_ACK`等状态，以及恢复遥测是否真正驱动自动清除。

### 5.2 认证与异常

- 有效账号获取JWT；
- 错误密码不签发JWT；
- 有效JWT获取当前用户；
- 无效JWT和缺失JWT返回401；
- 格式正确但不存在的资源ID返回404；
- 客户用户访问租户级列表返回403。

### 5.3 权限矩阵

| 资源/功能 | 租户管理员 | 客户用户未授权 | 客户用户已授权 |
|---|---|---|---|
| 客户管理、规则链 | 管理 | 不可见 | 不可见 |
| 测试资产 | 管理 | 不可见 | 查看 |
| 测试设备 | 管理 | 不可见 | 查看 |
| 测试仪表板 | 编辑 | 不可见 | 只读 |
| 关系中的未授权实体 | 可见 | 不可见 | 授权目标后可见 |
| 撤销后的资源 | 可管理 | 不可访问 | 撤权后立即失效 |

## 6. 测试数据策略

- 测试资源统一使用`QA_`前缀，便于识别和清理；
- 搜索结果必须按名称定位目标对象，不能默认第一条就是目标；
- 实体ID只有在来源响应验证通过后才保存和复用；
- 自动化采用幂等准备：不存在才创建，已存在则校验；
- 不自动删除不明确归测试所有的共享数据；
- 密码、JWT、Cookie和设备访问令牌仅存放在本机或Jenkins Credentials中。

## 7. 准入与准出

### 准入

- Docker和ThingsBoard服务正常；
- `127.0.0.1:9091`可访问；
- 测试账号、设备配置和规则链基线存在；
- 本地秘密配置完整且未纳入Git。

### 准出

- P0场景执行并有证据；
- 接口回归失败数和错误数为0；
- 失败已区分产品、脚本、数据或环境原因；
- 报告不暴露凭据；
- 剩余风险和未完成范围明确记录。

## 8. 暂不覆盖

- 集群、高可用和灾备；
- Kafka、Cassandra等组件深度测试；
- 全协议兼容性；
- 大规模容量测试；
- 复杂渗透测试；
- 企业版专属功能。
